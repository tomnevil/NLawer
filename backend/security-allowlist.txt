# 判定：**不可达 + 上游拒绝修复**，双重理由。
#
#   ① 不可达：项目**不直接使用 ecdsa**，也未使用任何 ECDSA 曲线算法。
#      JWT 用的是对称算法 HS256（`app/config.py: ALGORITHM = "HS256"`），

#   ② 上游拒绝修复：python-ecdsa 官方将该类侧信道攻击**明确列为 out of scope**，
#      无计划修复，因此 `fix_versions` 为空——**不存在"升级即可解决"的路径**。
#      上游立场见：https://github.com/tlsfuzzer/python-ecdsa/security

#   复查条件：python-jose 若改为默认携带 cryptography 后端并移除对 ecdsa 的依赖

# PYSEC-2026-4298 —— python-jose ≤3.5.0 算法混淆防护被 DER 编码公钥绕过
#                    （CVE-2026-85394，CVE-2024-33663 的不完全修复；2026-10-15 披露）
# ---------------------------------------------------------------------------
# 判定：**本项目不可达**，单理由但每条都实证过。
#
#   漏洞前提：攻击者拿到服务端的**非对称公钥**，且解码时**未显式限定 algorithms**
#   （advisory 原文："pass verification when algorithms are not explicitly restricted"）。
#
#   ① 显式限定：两处 `jwt.decode`（`app/core/security.py:66` / `:76`）都传了
#      `algorithms=[settings.ALGORITHM]`（= HS256），没有"不传 algorithms"的调用点
#      （`grep -rn "jwt.decode" app/` → 仅此两处）。
#
#   ② 无公钥可拿：全仓 0 处 RS256/ES256/PS256/JWKS/public_key
#      （`grep -rn "RS256|ES256|PS256|JWKS|jwks|public_key" app/ --include=*.py` → 0 命中）；
#      JWT 全是对称 HS256，密钥是服务端自身的字符串 ⇒ 攻击者**没有公钥可用来构造混淆输入**。
#
#   ③ 无升级路径：受影响范围 `≤ 3.5.0`（last_affected），披露时**没有已修复版本**
#      （pip-audit 的 Fix Versions 为空）⇒ "升级解决"不存在，与 ecdsa 条目同型。
#
#   复查条件（任一触发即失效，必须删除本条并重评）：
#     1. 项目引入任何非对称算法、JWKS/外部密钥解析；
#     2. 代码里出现**不带** `algorithms=` 参数的 `jwt.decode`；
#     3. python-jose 发布 ≥3.5.1 的修复版（届时直接升级依赖并删本条）。
# ---------------------------------------------------------------------------
