# PYSEC-2026-1325 —— ecdsa 0.19.2 Minerva 时序攻击（P-256）
# ---------------------------------------------------------------------------
# 判定：**不可达 + 上游拒绝修复**，双重理由。
#
#   ① 不可达：项目**不直接使用 ecdsa**，也未使用任何 ECDSA 曲线算法。
#      JWT 用的是对称算法 HS256（`app/config.py: ALGORITHM = "HS256"`），
#      `app/core/security.py` 只调用 `jwt.encode/decode`，**从不调用 jwe**，
#      因此 ecdsa 仅作为 python-jose 的传递依赖被安装、从不被加载执行。
#      （grep `ecdsa|ECDSA|ES256|P-256` 于 app/ 下：0 命中）
#
#   ② 上游拒绝修复：python-ecdsa 官方将该类侧信道攻击**明确列为 out of scope**，
#      无计划修复，因此 `fix_versions` 为空——**不存在"升级即可解决"的路径**。
#      上游立场见：https://github.com/tlsfuzzer/python-ecdsa/security
#
#   复查条件：python-jose 若改为默认携带 cryptography 后端并移除对 ecdsa 的依赖
#            （或项目引入 ES256 等非对称算法），本条目立即失效，必须重新评估。
# ---------------------------------------------------------------------------

# ---------------------------------------------------------------------------
# PYSEC-2026-2263 / -3455 / -3456 / -3457 —— pyasn1 0.4.8 的 ASN.1 解码 DoS（4 项）
# ---------------------------------------------------------------------------
# 判定：**不可达 + 依赖闭包锁死**，双重理由。
#
#   ① 依赖闭包锁死：python-jose 3.4.0 声明 `pyasn1<0.5.0,>=0.4.1`。
#      即"能装上的 pyasn1 最高只有 0.4.8"，而修复版本是 0.6.3 / 0.6.4
#      → **在保留 python-jose 的前提下无升级路径**（实测 ResolutionImpossible）。
#
#   ② 不可达（本轮做了**运行时实证**，不是读代码猜的）：
#      - 这些漏洞的入口是"把**外部可控的** DER/BER/PKCS8 数据喂给 ASN.1 解码器"。
#      - 本项目 JWT 全是**对称 HS256**（`app/config.py: ALGORITHM="HS256"`），
#        密钥是服务端自己的字符串，**不存在任何非对称密钥/证书解析**。
#      - 实证：在真实 HS256 encode+decode 前后比对 `sys.modules`，
#        `pyasn1` / `jose.backends.rsa_backend` / `jose.backends._asn1`
#        **全部未被载入**，走的只有 `cryptography` 后端。
#      - 代码层：`grep -rn "pyasn1|import asn1" app/` → 0 命中。
#
#    复查条件（两条任一触发即失效）：
#      1. 项目引入任何非对称算法（RS256/ES256/PS256）或需要解析外部密钥/证书；
#      2. python-jose 放宽 pyasn1 约束（届时必须立即升级 pyasn1 并删除本条）。
#    守门脚本：`python verify_p1_supply_chain.py` 中的"可达性哨兵"会在
#      ①检测到非对称算法被使用、或②pyasn1 修复版已可安装 时**主动报失败**。
# ---------------------------------------------------------------------------
