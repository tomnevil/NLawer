## 一、产品概述与目标

### 1.1 产品定位

"律小智"是一款基于大语言模型（LLM）的智能法律助手，专注于为个人用户和小微企业提供低成本、高效率、可信赖的法律服务。产品以"让法律触手可及"为核心理念，通过自然语言交互降低法律知识壁垒，将传统法律服务的高门槛转化为标准化、自动化的数字体验。

### 1.2 产品愿景

成为个人与小微企业"随身法务部"，构建"AI 普惠法律 + 专业律师兜底"的双层服务体系，最终实现"咨询—文书—立案"的法律服务全链路数字化闭环。

### 1.3 核心痛点

| 用户群体 | 痛点描述 |
| --- | --- |
| 个人用户 | 遇到租房纠纷、劳动维权、消费投诉时，不知如何起草文书、计算赔偿，聘请律师成本高（通常 500 元/小时起）。 |
| 小微企业 | 缺乏专职法务，合同审查、劳动合规、股权协议等依赖外部律师，单次咨询费用 2000-5000 元，初创期难以承受。 |

### 1.4 产品目标

| 阶段 | 周期 | 目标 |
| --- | --- | --- |
| 短期 | 0-6 个月 | 上线核心功能，覆盖 80% 常见法律场景（合同审查、文书生成、基础咨询），用户满意度 ≥4.5/5.0。 |
| 中期 | 6-12 个月 | 建立合规扫描引擎，为小微企业提供年度合规体检，签约 1000 家企业客户。 |
| 长期 | 1-3 年 | 成为区域性法律科技基础设施，对接法院、仲裁委等官方系统，实现"咨询-文书-立案"闭环。 |

### 1.5 成功指标

| 维度 | 指标 | 目标值 |
| --- | --- | --- |
| 用户侧 | 月活用户（MAU） | ≥5 万 |
| 用户侧 | 人均会话数 | ≥3 次 |
| 用户侧 | 文书生成采纳率 | ≥70% |
| 商业侧 | 付费转化率 | ≥8% |
| 商业侧 | 小微企业客单价（ARPU） | ≥2000 元/年 |
| 技术侧 | 回答准确率（基于律师标注） | ≥90% |
| 技术侧 | 引用溯源完整率 | 100% |

| 差异化 | AI+律师双签、法规实时溯源、区域化合规 | 自动化申诉流程 | 模板丰富、中文场景 | 合同管理深度 |

**律小智差异化竞争策略**

1. **可信优先**：全量引用溯源 + 高风险场景人工复核，建立用户信任壁垒。
2. **区域深耕**：优先覆盖广西及华南地区地方法规与裁判口径，形成区域性数据优势。
3. **双签服务**：与本地律所合作，提供"AI 生成 + 律师背书"的付费增值，兼顾低价与专业。

## 四、核心功能规格

### 4.1 智能问答（Legal Q&A）

**功能描述**：用户以自然语言提问，AI 基于法律知识库生成回答，并附带来源依据。

**交互流程**：

1. 用户输入问题（支持文字/语音/图片上传，如合同照片）。
2. 系统识别意图（咨询类/文书类/计算类）。
3. 调用 RAG 检索相关法规、案例、模板。
4. 生成结构化回答：结论 → 法律依据 → 行动建议 → 风险提示。

**输出结构规范**：

```text
【结论】一句话给出明确判断或处理方向
【法律依据】引用具体法规名称、条款号、条文摘要（可点击溯源）
【行动建议】分步骤可执行操作（含时限、材料、受理机关）
【风险提示】指出不确定性、时效性问题及后续后果
【免责声明】"本内容由 AI 生成，仅供参考，不构成法律意见"
```

**边界处理**：涉及复杂诉讼策略、跨国法律、非中文问题时，提示"建议咨询专业律师"并提供转介入口。

**典型问题意图分类**

| 意图类型 | 示例 | 处理引擎 |
| --- | --- | --- |
| 咨询类 | "被辞退能拿多少赔偿？" | RAG + LLM |
| 文书类 | "帮我写一份欠条" | 文书生成工作流 |
| 计算类 | "加班费怎么算？" | 代码节点计算 + LLM |
| 审查类 | "这份合同有什么风险？" | 合同审查模式 |
| 流程类 | "劳动仲裁怎么立案？" | 流程指南 + 材料清单 |

### 4.2 文书自动化（Document Automation）

**模板库**：覆盖 200+ 常用法律文书（劳动合同、租赁合同、欠条、离婚协议、公司章程等），按生命周期分类管理（劳动用工 / 合同交易 / 婚姻家庭 / 公司治理 / 诉讼文书）。

**生成流程**：

1. 用户选择文书类型，通过多轮对话收集关键变量（如甲方/乙方、金额、期限）。
2. AI 自动填充模板，生成初稿。
3. 用户可在线编辑，AI 实时提示风险点（如违约金过高、管辖法院不利）。
4. 导出为 Word/PDF，支持电子签名（集成第三方 CA）。

**差异化能力**：支持"合同审查模式"——用户上传已有合同，AI 标注风险条款并给出修改建议。

**文书变量采集规范**：每类文书定义结构化变量表（必填/选填、数据类型、校验规则），多轮对话仅追问缺失必填项，避免冗长。

**高风险文书清单（需人工复核）**：离婚协议、遗嘱、股权转让协议、认罪认罚相关文书等，强制插入律师复核节点。

### 4.3 合规扫描（Compliance Scanner）

**适用对象**：小微企业。

**扫描维度**：

| 维度 | 扫描要点 |
| --- | --- |
| 劳动用工 | 劳动合同签订率、社保缴纳、加班费计算、竞业限制。 |
| 商业合同 | 违约条款、知识产权归属、争议解决方式。 |
| 数据隐私 | 个人信息收集、Cookie 政策、用户协议合规性。 |
| 广告营销 | 绝对化用语、虚假宣传、专利标注。 |

**输出报告**：风险等级（高/中/低）、整改建议、参考模板、法规链接。支持定期（月度/季度）自动扫描。

**报告结构**：

```text
一、总体风险概览（风险评分 + 风险分布图）
二、分维度明细（每条风险：位置/原文 → 风险等级 → 依据条款 → 整改建议 → 参考模板）
三、合规行动清单（按优先级排序，可勾选跟踪）
四、历史趋势（多次扫描对比，评估整改成效）
```

### 4.4 引用溯源（Citation & Traceability）

- 所有回答必须附带来源：法律法规名称及条款、司法解释、指导性案例编号。
- 展示形式：点击引用标记，侧边栏弹出原文摘要，确保可验证性。
- 版本控制：法律条文更新时，自动标记历史回答的时效性变化。

**溯源完整性要求**：每一条结论性陈述必须至少对应一个可点击的引用来源；引用缺失视为生成失败，计入"引用溯源完整率"指标（目标 100%）。

## 六、技术架构要求

### 6.1 LLM 选型策略

| 场景 | 模型选择 | 理由 |
| --- | --- | --- |
| 通用问答/文书生成 | 混合部署：Qwen3.8-Flash（低成本）+ GLM-5.3-Flash（高精度） | 平衡成本与质量，通过路由层动态分配。 |
| 复杂推理/合规分析 | DeepSeek V4（满血版） | 逻辑推理能力强，适合长文本分析。 |
| 私有化/敏感数据 | 本地部署 Qwen2.5:32B（量化版） | 数据不出域，满足企业合规要求。 |

**模型路由规则（示例）**：意图简单且 token 消耗低 → 低成本模型；涉及赔偿计算、合规判定等复杂推理 → 高精度/满血模型；企业敏感数据 → 本地私有化模型。

### 6.2 RAG 知识库

**数据源**：

- 国家法律法规数据库（实时同步）。
- 最高人民法院指导案例、公报案例。
- 地方法规（支持省市级筛选）。
- 优质合同模板库（经律师审核）。

**检索增强**：

- 混合检索：BM25（关键词）+ 向量检索（语义）。
- 重排序（Rerank）：使用 bge-reranker-v2-m3 提升精度。
- 知识图谱：构建"法条-案例-文书"关联网络，支持多跳推理。

**知识库更新机制**：法规变更时通过监控管道捕获变更源 → 自动标记 + 每周人工审核 → 同步更新索引与历史回答时效性标记。

### 6.3 工作流编排

- **框架**：采用 Dify 或自研 Workflow 引擎。
- **节点类型**：
  - LLM 节点：问答、生成、摘要。
  - 代码节点：赔偿计算、日期推算、格式校验。
  - 条件分支：根据用户意图、风险等级路由。
  - 人工审核节点：高风险文书（如离婚协议）强制插入律师复核。
- **可观测性**：记录每个节点的输入输出、耗时、token 消耗，用于优化。

### 6.4 系统架构分层

```text
┌─────────────────────────────────────────────┐
│  客户端：移动端 App / Web / 微信小程序        │
├─────────────────────────────────────────────┤
│  接入层：API 网关、鉴权、限流、HTTPS/TLS1.3  │
├─────────────────────────────────────────────┤
│  应用层：问答、文书、合规扫描、溯源、企业后台  │
├─────────────────────────────────────────────┤
│  编排层：Dify/Workflow、模型路由、人工审核队列 │
├─────────────────────────────────────────────┤
│  能力层：RAG、知识图谱、Rerank、多模态解析    │
├─────────────────────────────────────────────┤
│  数据层：法规库、案例库、模板库、用户数据     │
│          （AES-256 加密，KMS 管理密钥）       │
└─────────────────────────────────────────────┘
```

### 6.5 对外接口规划（V2.0）

- 开放 API：面向合作律所、企业 OA 的标准化接口（文书生成、合规扫描、问答）。
- 法院/仲裁委对接：立案材料预生成、电子送达接口（需官方授权）。
- Webhook：企业合规报告推送、律师复核结果回调。

## 七、关键非功能性需求

### 7.1 数据安全与隐私

| 项 | 要求 |
| --- | --- |
| 传输加密 | 全站 HTTPS，API 通信使用 TLS 1.3。 |

### 7.2 合规性与免责声明

- 显式提示：每次回答开头注明"本内容由 AI 生成，仅供参考，不构成法律意见"。
- 律师背书：与律所合作，高风险场景提供"AI+律师"双签服务。
- 监管适配：遵守《生成式人工智能服务管理暂行办法》，完成算法备案。

### 7.3 可解释性

- 决策透明：AI 给出建议时，必须说明"为什么"（如"因为《劳动合同法》第 82 条规定…"）。
- 置信度提示：对低置信度回答（如罕见案例），明确告知"此回答可靠性较低，建议人工核实"。
- 用户反馈闭环：支持"踩"按钮，收集错误案例用于模型迭代。

## 九、数据分析指标体系

### 9.2 指标体系

| 层级 | 指标 | 定义/口径 |
| --- | --- | --- |
| 活跃 | MAU / WAU / DAU | 标准活跃用户口径。 |

| 质量 | 文书采纳率 | 用户导出/下载且未大改的文书 / 生成的文书。 |
| 转化 | 注册→首次生成转化率 | 首次完成文书生成的新用户 / 注册用户。 |
| 转化 | 免费→付费转化率 | 付费用户 / 注册用户。 |

- 每季度：等保/ISO 认证复核、安全演练、风险矩阵更新。
