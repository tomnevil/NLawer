## 0. 一句话

核 `display` 档时顺带发现：`verify_typography.py` 的 **T2b 检查集合是硬编码的 `CUSTOM_SIZES`
（10 个语义档）**，而字号档的**真源是 `tailwind.preset.ts`（17 档）**，两者之间**没有任何机械校验**
⇒ **preset 新增一个档，四条判据没有一条会红**，而 `cn()` 照旧把它当颜色吞掉
（字号静默回落继承值）。**这是 `#42` 完全相同的缺陷形状，只是可被「加一个档」重新打开。**
已把硬编码清单**删除**，改为**从 preset 派生 + 实跑生存探针**（新判据 **T2c**）。

## 1. 起因：`display` 档那一条的结论是「不是缺陷」

前一轮列为「待核」：`CUSTOM_SIZES` 列了 `display`，但产物 CSS 里 `.text-display` 不存在。

核实结论 —— **不是缺陷**：

| 检查 | 结果 |
|---|---|
| `tailwind.preset.ts` 有 `display` 定义吗 | **有**（`display: ["38px", { lineHeight: "1.25", fontWeight: "600", … }]`） |
| 源码里有 `text-display` 的用法吗 | **0 处**（`grep -rn "text-display" apps/ packages/` 为空） |
| 产物 CSS 里 `.text-display` | **0 处** —— **符合预期**（Tailwind JIT 只生成**被用到的**类） |
| 对照：`.text-h1`（有人用） | **1 处** ⇒ 证明产物 CSS 解析本身是通的 |

⇒ 「preset 有定义 + 无人使用 + 产物里没有」是**正常三连**。判据的档清单**不该**按「产物 CSS 里有没有」
来判断 —— 它是「`cn()` 必须认识的档」清单，与「当前有没有人用」无关。

## 2. 🚨 真正的缺陷：检查集合是第二份手写清单

```
真源：frontend/tailwind.preset.ts        fontSize 17 档（10 语义 + 7 存量）
  ↓ ？——**没有任何机械校验**
判据：evidence/verify_typography.py      CUSTOM_SIZES 10 档（硬编码元组）
  ↓ ？——**没有任何机械校验**
配置：frontend/packages/ui/src/lib/cn.ts FONT_SIZE_TOKENS 10 档
```

`verify_typography.py` 里**原来只有一处**把三者绑起来：

```python
missing = [s for s in CUSTOM_SIZES if s not in merge_sizes]   # 只查 CUSTOM_SIZES ⊆ cn.ts
```

**两处失守**：

1. **`preset → CUSTOM_SIZES` 无校验。** 往 preset 加一个语义档（例如 `h5`），
   `CUSTOM_SIZES` 不会自动包含 ⇒ **T2b 根本不检查 `text-h5`**。
2. **`missing` 只比清单、不比行为。** 它检查的是「清单里的名字在不在另一份清单里」，
   **不是**「这个档在 `cn()` 里会不会被吞」。清单之间可以**一起错**。

⇒ 后果与 `#42` 一模一样：`cn("text-h5", "text-ink-700")` ⇒ 两者同组 ⇒ 颜色赢 ⇒
`text-h5` 被删 ⇒ 字号**静默回落继承值** ⇒ 行高按继承字号算。
**而 T1/T1b/T1c/T2/T2b 没有一条会红。**

> **这就是坑 63 的同一个坑，但换了一个面**：
> 坑 63 讲的是「**期望值**必须读产品真正用的那一份」；
> 本条讲的是「**被检查对象的集合（分母）**也必须读真源」。
> 判据里**只要出现第二份手写清单，就一定会漂移**。

## 3. 修法：删掉手写清单，改为从 preset 派生 + 实跑

### 3.1 删除 `CUSTOM_SIZES`

```diff
 LH_FLOOR = 1.65
-CUSTOM_SIZES = ("caption", "label", "body-sm", "body", "body-lg",
-                "h4", "h3", "h2", "h1", "display")
+# 🚨 2026-09-24 删除：字号档的真源是 preset，判据里不该有第二份手写清单（坑 63）。
+#    现由 `parse_preset_sizes()` 直接派生，见 `judge_size_registration`（T2c）。
```

### 3.2 T2b 的迭代集合改为 preset 派生

```diff
-            for s in CUSTOM_SIZES:
+            for s in sorted(sizes):          # sizes = parse_preset_sizes()
                 tok = f"text-{s}"
                 if tok in itoks and tok not in mtoks:
```

⚠️ 多出来的 7 个存量档**零成本**：T2b 只在 `tok in itoks`（**源码里真的出现**）时才判，
存量档（`xs/sm/base/lg/xl/2xl/3xl`）twMerge 默认就认识 ⇒ 不会被误报。

### 3.3 新增 T2c：**实跑生存探针**（不是比清单，是比行为）

```python
def size_registration_probe_blocks(sizes):
    return [[f"text-{s}", "text-white"] for s in sorted(sizes)]   # 必然的颜色类

def judge_size_registration(sizes, project_merged):
    """preset 的**每一个**字号档，在**项目 merge 配置**下都必须存活。"""
```

- 形状与既有机制臂 M1/M5 **完全一致**（`text-<档>` + `text-white`）⇒ 复用已验证的机制。
- 输出**带修法**：`修法：把 {s} 加进 frontend/packages/ui/src/lib/cn.ts 的 FONT_SIZE_TOKENS`。
- **不接收任何硬编码档名** ⇒ 天然跟随真源，**构造上不可能漂移**。
- 探针跑不了（真实 twMerge 不可用）⇒ 走 **env 通道**（「取不到」≠「0 条合格」）。
- 用 `is not None` 而非真值判断：`cn.ts` 登记为**空列表**也是一种产品状态，
  此时应**报红**，而不是走「探针跑不了」。

### 3.4 替换掉 `missing`

```diff
-        missing = [s for s in CUSTOM_SIZES if s not in merge_sizes]
-        if missing:
-            problems.append(f"[T2b] … 未登记语义档 {missing} …")
+        if probe_merged is None:
+            env.append("[T2c] 档登记生存探针跑不了（真实 twMerge 不可用）⇒ 本次不判")
+        else:
+            problems += judge_size_registration(sizes, probe_merged)
```

⇒ **更强**（覆盖全部 17 档，含存量档）且**不再有第二份清单**。

## 6. 未验证边界（**必须说清**）

- **T2c 只判「preset 的档在 `cn()` 里活不活」，不判「该不该有这个档」。**
  `display` 定义了但无人使用 ⇒ T2c **不报**（这是**设计系统的取舍**，不是 `cn()` 的问题）。
- **存量档（`xs/sm/…/3xl`）也被 T2c 覆盖** —— 若有人把 `sm` 从 twMerge 默认配置里挤掉，
  T2c 会报。**这是有意的**（更宽的网），但**意味着 T2c 的「0 条」比原来更强**，不是同一条断言。
- **`probe_cn_render_delta.py` 仍留一份 10 档清单** —— 那是**一次性历史探针**（复现 `#42` 的
  改前/改后渲染证据）。已把注释改为指向 **preset**，并写明「新增语义档时**这里需手工跟上**
  （判据侧已不需要）」。**未把它改成派生**：它是一次性仪器，改动会让当时证据不可复现。
- **`BODY_SIZES = ("body-sm","body","body-lg")` 仍是硬编码** —— 它是**判据的语义判断**
  （§3.2「用途」列里哪些算正文档），**不是真源的副本**。若 §3.2 改版，**需人工跟**。
  ⚠️ 与 `CUSTOM_SIZES` 性质不同：`CUSTOM_SIZES` 是「真源的子集副本」（可派生），
  `BODY_SIZES` 是「判据自己的口径」（不可派生）。**这个区别是本条最有价值的部分**。
