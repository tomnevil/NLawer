仪器改动存证：`verify_typography.py` 的 **T4 从「只报不判」升级为真判据**
任务 #57 · 2026-09-24 · 起因 = 覆盖率审计**第二遍**把 §3.3 规则 3 列为「真·零判据」
═══════════════════════════════════════════════════════════════════════════════

【1】改的是什么（一句话）

`judge_rule3` 此前**只数 `cjk-gap` 的调用点、一句断言都没有** —— 属 README 坑 58 说的
「**只报告不判定**」：既不变红、也没人会读第 N 次运行里的同一行。

现在**补上判据**：
  **`styles.css` 里 `html .cjk-gap { margin-inline: … }` 的值
    必须 == 规范 `design-spec.md` §3.3 **现读**的那个 em 值。**
（与 ⑦ `--page-pad` 的 A1 **同形**：**钩子值必须等于规范现读值**。）

**仍然只报**：`cjk-gap` 的**调用点数** —— 「哪些中英混排处**该**加间隙」需要**语义**判断，
静态数不出来（同族：README 坑 60「**可静态近似是需要当场实测的主张**」）。
⇒ **这两件事必须分开写**：一个是判据，一个是信号。

（= 项目里骂过的「**静默的谎言**」）。

【3】为什么期望值要**现读规范**，而不是硬编码 `0.25em`

硬编码会让「**规范改了、CSS 没改**」**静默通过** —— 那正是 ⑦ `--page-pad` 那次的教训
（令牌值与规范必须同步，改一边就该红）。
⚠️ 但现读带来一个新风险：**规范文本一改，锚点可能读不到** ⇒ 这时必须报
**「我没测成」（exit 2）**，**不能**报成产品缺陷（否则是**假红**）。
⇒ 所以 §2 的第 4/5/6 条是**配套的**，不是可选项。

【4】三语义分档（写死在这里，免得下一个人改错）

| 情形 | 判定 | 理由 |
|---|---|---|
| 规范锚点命中 **≠ 1** 处 | **env（exit 2）** | **我读不到期望值** = 仪器/规范文本变了。**不是**产品缺陷 —— 别去改 CSS |
| 扫描集里没有 `packages/ui/src/styles.css` | **env** | 拿不到实际值 |
| `html .cjk-gap` 块命中 **> 1** 处 | **env** | 解析不了（锚点不唯一） |
| `html .cjk-gap` 块命中 **0** 处 | **problem（rc 1）** | **东西被删了** ⇒ 钩子没了（与「解析不了」**必须分开**：混了不是假红就是假阴性） |
| 块在，但**没有 `margin-inline`** | **problem** | 钩子存在但不生效 |
| 值取到了，但**值 ≠ 规范现读值** | **problem** | 钩子与规范不同步 |

⚠️ 上表的「0 处 ⇒ rc 1 / >1 处 ⇒ exit 2」不是随手分的，是项目既有那条纪律
（**「东西被删了」与「我的解析失败」必须分成两个退出码**）。

【6】注入反证（**在真仓库文本上**，一个产品文件都没碰）

手法：把真实的 `styles.css` / `design-spec.md` 文本读进来，**在内存里**改值再喂给判据
（比临时改产品文件安全：不留残留、不影响并行会话）。存证 `t4_inject_2026-09-24.txt`：

| 臂 | 注入 | 期望 | 实测 |
|---|---|---|---|
| 基线 | 不改 | problems 0 / env 0 | ✅ 0 / 0（且打出「== §3.3 现读值」） |
| **A** | **产品侧** CSS `0.25em` → `0.3em` | 1 / 0 | ✅ 1 / 0 |
| **B** | **规范侧** `0.25em` → `0.3em` | 1 / 0 | ✅ 1 / 0 ← **证明「改规范不改 CSS」也会红** |
| **C** | 规范锚点改到读不到 | **0 / 1** | ✅ 0 / 1（env，**未**报产品缺陷） |

⚠️ **A 与 B 两条都要有**：只测 A 只能证明「产品改错会红」，
**证明不了**「规范改了对不对会被发现」—— 而后者才是「现读」这个设计的全部意义。

⚠️ **自检臂覆盖 `if` 两侧**：C3（值相等 ⇒ 绿）+ C3b（且**确实判了**、不是静默跳过）
+ C4（值不等 ⇒ 红）—— 因为项目栽过一次：**一个一直为真的条件，它的 `if` 侧
可能从写下那天起就没执行过**（`--page-pad` 的 `any()` 返回 bool ⇒ 打出 `--True` 没人看见）。

【7】未验证边界

1. **只判了「钩子的值」，没判「间隙的实际视觉效果」** —— 0.25em 间隙是否真的解决了
   「3件」这类粘连，需要**渲染级实测字符间距**，本门禁**不做**（也不该由它做）。
2. **调用点数 0 处这个「功能缺口」仍在** —— 本改动**没有**修产品，
   只是把「值对不对」变成了判据；「该不该用」仍是只报。
3. `--source-only` 现在**能返回 exit 2**（规范锚点读不到时）。
   已核对运行器：`judge_ratchet()` 对 `rc == 2` 的处理是
   「环境问题 ⇒ 本次**不给结论**（跳过不是通过）」⇒ **不会误判成棘轮红**。
   ⚠️ 但这条**是读源码得出的**，**没有**真的造一次 exit 2 去跑运行器验证。
4. 本次**未跑** `--self-test` 之外的浏览器路径；四端 dev server 未启动。
