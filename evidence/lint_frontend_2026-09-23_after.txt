# 前端 lint 实测 · **改后**（待裁定 ⑤ 落地 · 2026-09-23）
#
# 命令：cd frontend && pnpm lint </dev/null        （非 TTY，复刻 CI 环境）
# 退出码：1
#
# 关键：**退出码没变（1 → 1），但性质完全变了。**
#
#   · 改前：脚本**存在**，跑起来是 `next lint` ⇒ 进入交互式 ESLint 初始化向导
#           ⇒ 「**静默说谎**」：`package.json` 声称有 lint，实际一个文件都没检查。
#           ⚠️ 在 CI 里（非 TTY）它会**卡在向导上然后 Cancel**，看起来像「跑过了」。
#   · 改后：脚本**不存在** ⇒ pnpm 直接报 `Command "lint" not found` ⇒
#           **大声失败**，不可能被误读成「lint 通过了」。
#
# ⇒ 纪律：**「响亮的缺席」优于「静默的谎言」。**
#    一个「存在但从不生效」的门禁，与没有门禁在效果上无法区分（同 README 坑 45），
#    而且它更坏 —— 它会让后来的人**以为这一类问题已经有人管了**。
#
# ⚠️ 实测边界：本机是 Windows + Git Bash，pnpm 在「脚本不存在」时会退化成调用 shell，
#    于是先看到 `'lint' 不是内部或外部命令`（cmd 的报错），再是 pnpm 自己的
#    `Command "lint" not found`。Linux CI 上只会看到后者。**两者都是 exit 1。**
# ⚠️ 本机终端编码把 pnpm 的框线字符渲染成乱码（`鈥塃RR_PNPM_…`），
#    语义就是 `ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL  Command "lint" not found`。
