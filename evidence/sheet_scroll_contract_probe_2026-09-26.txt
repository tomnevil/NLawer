【第一轮】evidence/probe_pulltorefresh_in_sheet.py  （2026-09-20 既有探针，已登记 NON_GATE_SCRIPTS）
  问：PullToRefresh 装进 BottomSheet，朴素嵌套会不会套两层滚动？
  臂 A 朴素嵌套 / B 根加 height:100% / C 对照（只有内层）
-------------------------------------------------------------------------------

── 臂 A：朴素嵌套（PullToRefresh 根**不加高度**）
   根高 1600px
   外层 .bs-content   clientH=  361  scrollH= 1632  滚到底后 scrollTop=1271
   内层 .ptr-scroll   clientH= 1600  scrollH= 1600  滚到底后 scrollTop=   0
   → 内层可滚=False  外层在滚=True  内层能表达「不在顶部」=False

── 臂 B：根加 `height:100%`
   根高 329px
   外层 .bs-content   clientH=  361  scrollH=  361  滚到底后 scrollTop=   0
   内层 .ptr-scroll   clientH=  329  scrollH= 1600  滚到底后 scrollTop=1271
   → 内层可滚=True  外层在滚=False  内层能表达「不在顶部」=True

── 臂 C：对照：只有内层滚动（= BottomSheet 把滚动权交给调用方）
   根高 361px
   外层 .bs-content   clientH=    —  scrollH=    —  滚到底后 scrollTop=   —
   内层 .ptr-scroll   clientH=  361  scrollH= 1600  滚到底后 scrollTop=1239
   → 内层可滚=True  外层在滚=False  内层能表达「不在顶部」=True

==========================================================================
判定：
  [A] 朴素嵌套 ⇒ **外层在滚、内层滚不动**（内层 clientH == scrollH）
      ⇒ 内层 `scrollTop` 恒为 0 ⇒ `PullToRefresh` 的 `scrollTop > 0` 守卫**失效**：
         列表滚到中段后上滑，仍会被判成「在顶部」而触发刷新。
  [B] 根加 `height:100%` ⇒ **内层独占滚动、外层不再滚** ⇒ 守卫可用 ✓
  [C] 对照（单层）⇒ 内层独占滚动 ✓（与 B 同结果，说明 B 的写法把结构收敛回了单层）

结论：**`BottomSheet` 的内容区目前会和外层滚动打架**。
  · 朴素嵌套**不可用**（守卫失效，刷新手势会无视滚动位置触发）；
  · 加 `height:100%` 能收敛成单层，但它**依赖外层的 padding / flex 恰好如此**——
    属于「碰巧对」，不是「由构造对」。
  ⇒ 建议给 `BottomSheet` 增加一个「把滚动权交给调用方」的开关
    （或让 `PullToRefresh` 接受外部滚动元素），再接 NR-11。

【勘误 · 2026-09-26】第二轮 a 的 F 臂「判定」一行写错了 —— 以原始测量为准
-------------------------------------------------------------------------------
  2a 探针的判定逻辑**只看了 innerOverflows**，漏看「第一个子元素被压成 0 高」
  ⇒ 它把 F 臂写成「契约可放宽」。这是**仪器缺陷**，不是结论。
  🚨 原始测量是 F 臂 `调用方高=   0`（表头被压成 0 高 ⇒ 隐形）。
  ⇒ 正确结论：grid 槽位**不支持多子元素**，契约**不能放宽**。
  2b 探针已把「子元素被压成 0 高」纳入判定（其输出里的『各子元素未被压扁』一项）。

  ⇒ 最终结论：**content 模式的槽位用 flex-col**（支持 N 个子元素，臂 S 成立：
     表头 34px / 内层 293px / 页脚 34px）；grid 只支持单子元素（臂 F 表头被压扁）。
  ⚠️ 另一条同样重要：flex 槽位下，若调用方**再包一层 flex 却忘了 min-h-0**（臂 Q），
     调用方会被撑到 1600px、内层滚不动（scrollTop 恒 0）⇒ 契约必须写出这条义务。

  [P] 期望布局正确 实测布局正确 ✓

结论（与 §9 第 10 项定稿 ① 一致）：
  · 槽位**必须用 `flex` 列** —— `grid-rows-1` 只支持**单**子元素
    （臂 F 的表头被压到 13px，其自然高度是 34px）；
    而通知中心的内容天然是「表头 / 滚动列表 / 页脚」**三段**（臂 S 成立）。
  · `flex` 槽位下调用方**两条义务**：① 滚动层 `flex-1`；
    ② 再包一层 `flex` 时必须带 `min-h-0`（否则臂 Q 的形态：内层 `scrollTop` 恒 0、**静默失效**）。
