## 📌 TL;DR

- **① A3 事实结论：无老集成方。** 合同审查同步接口的唯一调用方是**自建 web 前端**（JWT 用户会话），后端**不存在任何入站外部集成机制**（无 API-Key 校验、无 webhook、无 partner/开放平台）。故「为兼容老集成方而保留同步大文本入口」的理由**不成立**。
- **⚠️ 但调查中发现一个此前未识别的阻塞**：**异步合同审查通道不存在** —— `JobType` 仅 4 类（`case_analysis`/`evidence_parse`/`compliance_scan`/`document_gen`），**没有 `contract_review`**。而 B1 选项①（存 .txt 上传 → 触发异步合同审查）**依赖它**。
- **⇒ A3 裁定：保留同步 20k（选项①），但定性为「过渡态安全网」**；同时把「新建 `JobType.CONTRACT_REVIEW` 异步通道」列为 **I1 增补项**，建成并验证后切换为「>20k 强制异步」。理由：既不为不存在的集成方付兼容税，也不在异步通道建成前给用户制造死路。
- **② 五个开放项全部裁定**：web **进 v1**（修正原定 lawyer+admin）· 计数用**字符** · 第三选项**不进 v1**（但草稿恢复必须进）· 令牌**零新增色值**（改为 7 个语义别名，修正原草案「新增 7 个色值」的错误）· SMTP **不进 v1 关键路径**。

## ① A3 — 老集成方事实调查

### 1.1 调查方法

针对「是否存在依赖 `source_text` 同步接口的老集成方」，查四类证据：**调用方 / 入站鉴权 / 端点形态 / 生产态**。

### 1.2 证据表

| # | 查证项 | 结果 | 出处 |
|---|---|---|---|
| E1 | **谁在调这个接口** | 仅**自建 web 前端**一处：`authed("/api/v1/documents/contract-review", {method:"POST", body:{source_text}})`；全仓 `frontend/` 只此一处调用 | `frontend/apps/web/app/(app)/contract-review/page.tsx:89` |
| E2 | **调用凭据** | `authed(...)` = **JWT 用户会话**（非 API Key / 非 M2M 令牌） | 同上 + `documents.py:166 Depends(get_current_user)` |
| E3 | **后端入站集成机制** | **不存在**。`backend/app` 内的 `api_key` **全部是出站**的 LLM/Embedding provider key；无入站 API-Key 校验、无 webhook 接收、无 partner/开放平台集成 | `ai/embeddings.py:24,102` · `ai/providers.py:29,54` |
| E4 | **WeCom/Feishu 是什么** | 是**出站通知占位**（「仅提供协议转换占位，不接真实飞书开放平台 API」），不是入站集成 | `app/im/feishu.py:3` |
| E5 | **端点形态** | `POST /contract-review` 要求 `get_current_user` + `get_tenant_context` ⇒ 外部系统**结构上无法**直接调用 | `api/v1/documents.py:161-167` |
| E6 | **生产态** | LLM 未配置（`llm_providers` 全 false）⇒ 尚未进入真实 AI 生产态，不可能已有外部生产集成方 | 项目硬约束 #5 |
| E7 | **同步上限现状** | `source_text: str = Field(..., max_length=20000)` **已上线**（I1 已完成） | `app/schemas/document.py:45` |

### 1.3 事实结论

> **无老集成方。** 「保留同步 20k」若是出于兼容考虑，该理由**不成立** —— 没有需要兼容的对象。

### 1.4 ⚠️ 但发现一个阻塞：异步合同审查通道不存在

| 查证 | 结果 |
|---|---|
| `JobType` 枚举成员 | 仅 **4 个**：`CASE_ANALYSIS` / `EVIDENCE_PARSE` / `COMPLIANCE_SCAN` / `DOCUMENT_GEN` |
| 是否有 `contract_review` job | **没有**（`models/enums.py:110-114`） |
| 影响 | B1 选项①「一键存 .txt 上传 → 触发**异步合同审查**」**依赖一个尚不存在的 JobType**；413 的 `guidance=upload_or_async` 目前指向一条**未建成**的路径 |

> 🚨 这是本次调查最重要的发现：**现在取消同步大文本入口，会让 >20k 用户无路可走** —— 不是因为要兼容谁，而是因为替代路径还没建。

### 1.5 ⇒ A3 裁定

**裁定：选项①（保留同步 20k），但定性为「过渡态安全网」，并附一个 I1 增补项。**

| 项 | 内容 |
|---|---|
| 当前 | 保留同步 20k（已上线）作为安全网；>20k 返 413 + `guidance=upload_or_async` |
| **I1 增补（新增）** | 新建 `JobType.CONTRACT_REVIEW` + 异步合同审查通道（对应 PRD 的「异步 500k」），并配判据（含反向向量） |
| 切换条件 | 异步通道**建成并通过判据验证**后，切换为「>20k 强制异步」，同步入口仅保留 ≤20k |
| 不变 | **严禁静默截断**（静默截断 ⇒ 结论基于残缺文本 ⇒ 静默错判） |

**为什么不是立刻选②（强制异步）**：选②的收益是「不为不存在的集成方付兼容税」，但代价是**在替代路径建成前制造死路**——而死路比兼容税严重得多。分两步可同时拿到两个收益。

## ② 设计草案 5 个开放项 · 裁定

### ②-1 web 是否进 v1 → **进 v1（修正原 PRD）**

**依据**：web 是**唯一已有合同审查页面的端**（`apps/web/app/(app)/contract-review/`），也是合同原文的**主场景**；瑞思的角色影响表里「客户 · 合同原文」是**最不能忍截断**的一类（截断 ⇒ 静默错判）。原 PRD 把 v1 定为 lawyer+admin，**漏掉了真正的承载端**。

- **裁定**：v1 覆盖 **web + lawyer + admin** 三端。
- **im**：**不做**。`SendMessageRequest.text` 上限 4k，远低于触发阈值，且即时消息不是长合同场景 ⇒ 保持「v2 或忽略」。

### ②-2 计数 N 用字符还是 token → **字符**

**依据**（决定性）：后端 `max_length=20000` 校验的是**字符数**（pydantic 对 `str` 校验 `len()`）。只有字符计数才能与后端 413 阈值**逐字对齐**；token 计数（中文 1 字 ≈ 1.5–2 token，英文 1 词 ≈ 1.3 token，**非线性**）会让前端预警与后端拒绝**错位** —— 表现为「前端没预警却被 413」，正是要消灭的「事后惩罚式拦截」。竞析口径也一致：**对外限字符（可前端校验、可预期），对内按 token 计费**。

### ②-3 第三选项「折叠原文继续问答」进 v1 否 → **不进 v1（进停车区）**

- **裁定**：③ **不进 v1**。v1 只保留 ①一键存 .txt 上传 ②选本地文件 —— 两者已覆盖主流路径。
- ⚠️ **必须与③切割的**：「关页后草稿恢复」是**零丢失验收点**，独立于③ ⇒ **必须进 v1**。别把两者绑在一起砍掉。
- ③ 的去留待 v1 埋点数据（选项选择分布）验证后再定。

### ②-4 令牌色值 → **零新增色值，改为 7 个语义别名**（⚠️ 修正原草案错误）

**原草案错误**：提议「新增 7 个色值令牌」—— 实际上 `packages/ui/src/tokens.css` 的 v2「墨与纸」体系**已完整覆盖**这些用途，新增色值会**污染共享设计系统**（且须拍板）。

**修正后方案**：**复用现有令牌 + 7 个语义别名**（别名 `var()` 引用已有变量 ⇒ 深色模式自动翻转，**零 `!important`**）。

| 用途 | 浅色取值 | 深色取值 | 来源 |
|---|---|---|---|
| 计数徽章 静置 | `--surface-subtle` #EFF1F3 / `--text-muted` #6B7480 | #1A1F26 / #9AA3AE | **复用** |
| 计数徽章 预警 ≥90% | `--pending-50` #FDF6E9 / `--pending-600` #8F5F14 (5.5:1) / 边框 `--pending-300` #E2BC70 | #2C220E / #DAA84E / #6E521E | **复用**（琥珀阶） |
| 决策门横幅 | `--info-50` #EFF5FB / 边框 `--info-200` #B8D4EB / 文本 `--info-600` #225C93 | #102232 / #20405E / #84BAE6 | **复用**（中性引导，非 danger —— 413 是「换条路走」，不是错误） |
| 进度条轨道 | `--brand-100` #D9E4F7 | #16305F | **复用**（注释即「进度条轨道」） |
| 进度条填充 | `--brand-500` #3660B0 | #4E77C4 | **复用**（注释即「进度条」） |
| 抽屉底 / 阴影 | `--surface-card` + `--s3` | 自动 | **复用**（`--s3` 注释即「模态、抽屉」） |

**7 个语义别名（零新色值）**：
```css
--progress-track: var(--brand-100);
--progress-bar: var(--brand-500);
--gate-banner-bg: var(--info-50);
--gate-banner-border: var(--info-200);
--gate-banner-fg: var(--info-600);
--count-warn-bg: var(--pending-50);
--count-warn-fg: var(--pending-600);
```
> 不需要 `--shadow-drawer`（用 `--s3`）、不需要 `--task-drawer-bg`（用 `--surface-card`）。别名在 `.dark` 下正确翻转：`var()` 是**使用时解析**（同文件内 `--actionbar-bottom` 已有先例）。

### ②-5 SMTP/企微资源归属 → **不进 v1 关键路径**

**依据**：SMTP/企微属**外部资源**，当前缺失（Q-K①/Q-L）；代码里 WeCom/Feishu 是**协议转换占位，不接真实平台**（E4）。缺凭据写的判据是**假绿**（C1）。

- **裁定**：v1 **只做应用内通知**（toast/红点）；企微/邮件列 **v2 硬依赖**。
- **不因缺 SMTP 阻塞 v1**；Q-K①/Q-L 保持挂起，待运维/客户提供凭据。
