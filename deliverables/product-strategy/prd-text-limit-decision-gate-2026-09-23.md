## 1. 问题陈述

I1 后端已为 18 个文本字段加 `max_length` 并上线 HTTP 413（`CONTENT_TOO_LARGE`），异步 `jobs` 能力也已就绪。但前端**完全没有承接层**：

1. 超限即丢内容 → 用户信任崩塌；
2. 无实时计数 → 用户写完才知超限（事后惩罚式拦截）；
3. 无可见任务中心 → 长任务「不确定等待」被误判为失败，引发重复提交或离开丢失结果。

413 与 `jobs` 能力已就绪，纯前端/UX 缺口阻塞了已上线后端价值的兑现，须立即补承接层。

## 2. 目标与非目标

**三个正交目标**

- **G1（零丢失承接）**：超限 413 时前端绝不清空已输入内容，提供非阻断决策门引导改文件上传/异步。
- **G2（可预期等待）**：长任务以阶段 + 百分比 + ETA 呈现，支持离开后回看、完成/失败通知与失败重试。
- **G3（统一拦截）**：全局一处拦截 413 并复用 `jobs` 端点与僵尸恢复循环，避免各端重复实现。

**非目标**

- 不改后端 413 语义（已成）；
- 不新建鉴权；
- 不依赖 I2/I3；
- B1/B2 与 A 组拍板**正交**（互不阻塞）；
- 不做文本自动摘要/截断（规范明示「不做截断」）。

## 3. 用户故事

- **US1（资深律师）**：粘贴 3 万字合同进「合同原文」框，达软上限即黄条预警；提交超限得 413，决策门一键把已输入存 .txt 上传转异步合同审查，原文不丢。
- **US2（助理偶发长文本）**：问答框写 4500 字问题触发 413，决策门「折叠原文继续问答」让其先聊，稍后补传。
- **US3（知识库运营）**：admin 批量导入 PDF 切片，任务中心看各文档阶段进度与 ETA，下班后企业微信收到「导入完成」通知。
- **US4（焦虑用户）**：长审查任务中误以为卡死，点开任务中心抽屉见「审查中 62%」+ ETA 8 分钟，安心离开。
- **US5（失败重试）**：合规扫描 FAILED，任务中心给「重试」钮，复用 `retry_count` / `JOB_MAX_RETRIES`。

## 4. 方案设计

### 4.1 B1 决策门

**用户流程**：输入 → 达 90% 软上限（黄色提示 + 上传钮）→ 提交触发 413 → 全局拦截渲染非阻断横幅决策门 → 三选项（①一键存 .txt 上传 ②选本地文件 ③折叠原文继续问答）→ 上传中/异步排队态 → 成功转任务中心。

**UI 状态**：正常（计数 X/N 灰）、预警（≥90% 黄 + 上传钮）、超限门（横幅 + 三选项，内容暂存）、上传中（进度）、异步排队（已入 jobs，提示去任务中心）。

**边界/错误**：网络中断 → 内容仍暂存本地可重传；上传失败 → 保留原文 + 重试；用户关页 → 已输入存草稿（IndexedDB/localStorage），重开恢复。

**硬约束**：全局拦截 413（含所有文本字段），**绝不清空**；错误体 `field` / `max_length` / `guidance` 直接驱动文案与计数上限 N。

### 4.2 B2 长任务进度条

**状态机**：`RECEIVED 已接收 → PARSING 解析切片 → REVIEWING 审查中 → REPORTING 生成报告 → SUCCESS 完成`（导入/扫描类同阶段化）；每态含百分比 + ETA + 心跳保活。

**任务中心**：抽屉式入口（四端右上角箱/铃图标），复用 `GET /api/v1/jobs` 分页 + `?status=` 过滤，按 `ctx.tenant_id` 隔离，自动对接 `recover_stale_jobs` 僵尸回收 → 渲染为可见任务箱。

**通知渠道**：应用内 toast/红点（v1）；企业微信/邮件（v2；⚠️ 邮件需 SMTP 资源，当前缺失 ⇒ 列为依赖/待办）。

**失败重试与持久化**：FAILED 显「重试」钮 → `POST /api/v1/jobs/{id}/retry`；结果持久化于 jobs，离开后可回看。

**涉及 `packages/ui`（需拍板）**：决策门横幅、计数徽标、阶段进度条、任务中心抽屉均为共享组件，需先出设计令牌规范、定稿后动工。

## 5. 技术考量

- **全局 413 拦截点**：在 `packages/sdk` 响应拦截器统一捕获 413 + `CONTENT_TOO_LARGE`，派发决策门事件；各端输入框订阅计数（X/N）。
- **jobs 对接**：任务中心直调 `GET /api/v1/jobs` 与 `retry`；前端轮询/WebSocket 心跳，复用后端恢复循环，不自建任务存储。
- **设计令牌变更**：新增 `--color-warn-soft`、`--progress-track/bar`、`--gate-banner` 等（清单见停车区）；改动需拍板。
- **四端范围**：lawyer（主，长文本 + 长任务）、admin（知识库导入长任务）、web（客户问答长文本，v1 可选）、im（消息 ≤4000，v2 或忽略）。v1 聚焦 lawyer + admin。

## 7. 验收标准

**B1**

- Given 用户在文本框输入，When 字数达上限 90%，Then 显示黄色预警与上传钮（软上限预警）。
- Given 用户提交超限文本，When 收到 413，Then 已输入内容完整保留，渲染决策门且提供三选项（存 .txt / 选文件 / 折叠继续）。
- Given 决策门已显示，When 用户选「一键存 .txt 上传」，Then 已输入文本写入 .txt 并触发异步任务，内容不丢。
- Given 用户触发 413 后关闭页面，When 重开，Then 原输入从草稿恢复（零丢失）。

**B2**

- Given 长任务运行中，When 用户在任务中心查看，Then 显示当前阶段 + 百分比 + ETA。
- Given 用户离开页面后返回，When 打开任务中心，Then 可回看该任务进度与结果（持久化）。
- Given 任务 SUCCESS，When 用户未在线，Then 应用内通知可达，企业微信/邮件（v2）送达。
- Given 任务 FAILED，When 用户点重试，Then 调 `retry` 且 `retry_count` 递增，状态回 RUNNING。
