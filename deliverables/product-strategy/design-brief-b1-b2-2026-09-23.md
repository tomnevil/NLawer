## 1. B1 决策门（413 非破坏承接）

### 1.1 用户流程（概念图）

```
┌─────────────┐   90% 软上限   ┌──────────────────┐   提交触发 413   ┌─────────────────────────────┐
│ 输入框输入 X/N│ ───────────→ │ 黄色预警+上传钮    │ ───────────────→ │ 全局决策门横幅（非阻断）      │
│ (正常 灰)    │              │ (CountBadge 黄)   │                 │ ① 存 .txt 上传              │
└─────────────┘              └──────────────────┘                 │ ② 选本地文件                │
                                                                    │ ③ 折叠原文继续问答          │
                                                                    └────────────┬───────────────┘
                                                                                 │ 选 ①/②
                                                                       ┌─────────▼──────────┐
                                                                       │ 上传中/异步排队态   │ ──→ 任务中心（B2）
                                                                       │ （原文零丢失）     │
                                                                       └────────────────────┘
```

### 1.2 实时计数（CountBadge）

- 每个受控文本框订阅 `X/N`：`X` = 当前字数；`N` = 该字段 `max_length`（取自后端 413 错误体 `max_length`，前端不再硬编码上限）。
- 软上限阈值 **90%**：`<90%` 灰、`≥90%` 黄 + 显示「上传」引导钮、`=100%` 提交即触发 413（不拦截输入，不截断）。
- ⚠️ **N 以字符还是 token 计未定**（开放问题④）：中英文混排体验差异大，需产品/设计拍板；草案默认**字符计**，待确认。

### 1.3 决策门（GateBanner）三选项

| 选项 | 行为 | 零丢失保证 |
|---|---|---|
| ① 一键存 .txt 上传 | 把已输入 `content` 转 `Blob` 存为 `.txt` → 触发对应异步任务（合同审查/知识库导入等）；成功转任务中心 | 原文封装进文件，不丢 |
| ② 选本地文件 | 打开文件选择器，附加/替换源文件再提交 | 原文仍在输入框，不丢 |
| ③ 折叠原文继续问答 | 原文存入草稿（IndexedDB），先继续对话，稍后补传 | 原文进草稿，可恢复 |

- **硬约束**：决策门展示期间**绝不清空输入框**；横幅为顶部非阻断提示，不阻断其余 UI 操作。
- **文案驱动**：横幅文案 `<field>` + 上限 `<max_length>` + `guidance=upload_or_async` 由 413 错误体直填，不写死。

### 1.4 错误/边界

- 网络中断 → 原文仍暂存本地，可重传；
- 上传失败 → 保留原文 + 「重试」；
- 用户关页 → 已输入存草稿（IndexedDB/localStorage），重开恢复（零丢失验收点）。

## 2. B2 长任务进度条 + 任务中心

### 2.1 状态机（概念图）

```
RECEIVED ──→ PARSING ──→ REVIEWING ──→ REPORTING ──→ SUCCESS
   │                                                        │
   └──────────────────── FAILED ──→ RETRYING ──→ (回 REVIEWING)
                              ↑________ retry_count < JOB_MAX_RETRIES ________│
```

- 每态展示：**阶段标签 + 百分比 + ETA + 心跳保活**。
- 导入/扫描类任务复用同一阶段化模型（阶段文案可配置）。

### 2.2 任务中心抽屉（TaskCenterDrawer）

- 入口：四端右上角铃/箱图标（红点 = 有进行中/完成未读）。
- 数据：直调 `GET /api/v1/jobs`（分页 + `?status=` 过滤），按 `ctx.tenant_id` 隔离；自动对接后端 `recover_stale_jobs` 僵尸恢复 → 渲染为可见任务箱。
- 轮询/WebSocket 心跳复用后端，前端**不自建任务存储**。

### 2.3 通知与重试

- 通知：应用内 `toast`/红点（**v1**）；企业微信/邮件（**v2**，⚠️ 依赖 SMTP/企微资源，当前缺失，见 Q-K①/Q-L）。
- 重试：`FAILED` 显「重试」钮 → `POST /api/v1/jobs/{id}/retry`，`retry_count` 递增、状态回 `RUNNING`。
- 持久化：结果存 jobs，离开后可回看（零丢失/可恢复验收点）。

## 3. packages/ui 令牌变更清单（待拍板）

> 遵循设计令牌迁移规范：CSS 变量 + 零 `!important` 深色模式；新增变量须定稿色值后再落地。

> ⚠️ **本节已按 2026-09-23 裁定修正**：初稿提议「新增 7 个色值令牌」是**错的** —— `packages/ui/src/tokens.css` 的 v2「墨与纸」体系**已完整覆盖**这些用途，新增色值会**污染共享设计系统**。
> **修正为：零新增色值 + 7 个语义别名**（别名 `var()` 引用已有变量 ⇒ 深色模式自动翻转，零 `!important`）。
> 裁定记录见 `rulings-a3-and-design-openitems-2026-09-23.md` §②-4。

| 用途 | 浅色 | 深色 | 来源 |
|---|---|---|---|
| 计数徽章 静置 | `--surface-subtle` #EFF1F3 / `--text-muted` #6B7480 | #1A1F26 / #9AA3AE | 复用 |
| 计数徽章 预警 ≥90% | `--pending-50` #FDF6E9 / `--pending-600` #8F5F14 / 边框 `--pending-300` #E2BC70 | #2C220E / #DAA84E / #6E521E | 复用（琥珀阶） |
| 决策门横幅 | `--info-50` #EFF5FB / 边框 `--info-200` #B8D4EB / 文本 `--info-600` #225C93 | #102232 / #20405E / #84BAE6 | 复用（中性引导，**非 danger** —— 413 是「换条路走」，不是错误） |
| 进度条轨道 | `--brand-100` #D9E4F7 | #16305F | 复用（注释即「进度条轨道」） |
| 进度条填充 | `--brand-500` #3660B0 | #4E77C4 | 复用（注释即「进度条」） |
| 抽屉底 / 阴影 | `--surface-card` + `--s3` | 自动 | 复用（`--s3` 注释即「模态、抽屉」） |

**7 个语义别名（零新色值）**：
```css
--progress-track: var(--brand-100);
--progress-bar: var(--brand-500);
--gate-banner-bg: var(--info-50);
--gate-banner-border: var(--info-200);
--gate-banner-fg: var(--info-600);
--count-warn-bg: var(--pending-50);
--count-warn-fg: var(--pending-600);
```

**新增共享组件**（均挂 `packages/ui`）：`GateBanner` / `CountBadge` / `StageProgress` / `TaskCenterDrawer` / `JobRow`。

🚨 **实现依赖（2026-09-23 新发现）**：`JobType` 仅 4 类，**没有 `contract_review`** ⇒ B1 选项①「存 .txt 上传 → 触发异步合同审查」依赖一个**尚不存在**的 JobType，须在 v1 内新建（见裁定记录 §①-1.4）。

## 4. 概念图汇总

- B1：输入 → 软上限预警 → 413 决策门（三选项）→ 上传/异步 → 任务中心。
- B2：任务状态机（5 阶段 + 失败重试）→ 任务中心抽屉（复用 jobs）→ 通知/重试。
- 全局：SDK 拦截器一处捕获 413，派发决策门事件；各端订阅计数，复用 jobs 与恢复循环。
