## 1. 事实核查（已核实，非推测）

1. **钩子存在且值正确**：`styles.css:60-62` 定义 `html .cjk-gap { margin-inline: 0.25em; }`；全仓库 `grep -rni 'cjk'` 只命中它自己的定义（admin-gap-analysis.md:1924-1925）。
2. **值已由门禁守**：`verify_typography.py` T4 的判据说「`html .cjk-gap` 的 `margin-inline` **必须 == §3.3 现读值**」（源码层断言，期望值从规范文件现读，非硬编码）。即「改规范不改 CSS / 改 CSS 不改规范」都会红。门禁**已覆盖「值漂移」**，这是 2026-09-24 那次升级补上的（此前 T4 只数调用点、零断言）。
3. **覆盖率只报**：T4 的第二件事是「调用点数」，明确标注 **只报不判**——它是「用没用」的覆盖率信号，不是断言。
4. **产品 0 调用点**：规范声明了，但产品没挂这个类 ⇒ §3.3 规则 3 实际未生效。
5. **实测缺口**：admin-gap-analysis.md 原文写道「需先实测『3 件』这类粘连是否真的发生 —— **本稿没做这个实测**，所以只报不判」。

## 2. 三个路径（待拍板）

| 路径 | 含义 | 后果 |
|---|---|---|
| **A · 产品接入** | 在中文长文容器挂 `cjk-gap` 类，让规范真正落地 | 覆盖率自然 >0；T4 覆盖率臂可随之从「只报」升为「判」 |
| **B · 升级门禁为「判」** | 把 T4 覆盖率从「只报」改成「判」（0 调用点即红） | **立刻让 CI 红**，等于强制 A 或 C；无实测支撑易把不存在的问题变硬性失败 |
| **C · 降级规范** | 若决定不追，把 §3.3 规则 3 改为「非强制 / 由字体侧承载」 | 与「只报」一致，不再有「未落地」的尴尬 |

---

## 3. 裁定建议（推荐顺序）

**不要现在就走 B（硬红 CI）。** 理由：

- **静态数调用点 ≠ 语义判断**：哪些中英混排处「该」加间隙需要语义判断，静态扫不出来（同族教训：`methodology` 里「每屏 ≤1 主色按钮」这类渲染期概念，不能靠源码数）。
- **没有实测支撑**：粘连是否真发生是 open question，admin-gap-analysis 自己承认没测。在没实测前强覆盖率，可能逼出无效接入或制造假红。
- **当前状态是自洽的**：值判据守着（防漂移），覆盖率只报（留痕 + 待决策）。这比「硬红但无依据」更诚实。

**推荐下一步**：

1. **第一步（低成本，建议做）**：渲染期实测——在现有中文长文页（web/qa 流式生成块、im 结构化分析卡等）量「CJK 字母夹在 ASCII 之间」的实际间距/粘连，确认是否真有视觉问题。
2. **第二步（按实测拍板）**：
   - 真有粘连 ⇒ **A**：在中文长文容器挂 `cjk-gap`（产品改动，需设计定稿），覆盖率 >0 后把 T4 覆盖率臂升为「判」。
   - 无粘连 / 不追 ⇒ **C**：§3.3 规则 3 降级为非强制，T4 覆盖率臂保留「只报」。
   - **不推荐**单方面走 B 而不做 A/C 任一。

---

## 4. 门禁影响

- 现有 T4 **值判据不动**（已 0 缺陷、已进 `browser-all`）。
- 覆盖率臂保持「只报」直至 A/C 拍板。
- 若走 A 并升级覆盖率臂为「判」：必须配**注入反证臂**（摘掉接入 ⇒ 该臂必红），遵循本项目「判据自缺陷」纪律。
