## 2. 方法：为什么必须**量像素**，不能只读 class

上一轮把这份清单按「令牌名」扫出来（`text-brand-600`），但**令牌名只说明作者想干什么，
不说明浏览器真的干了什么**。这次先做一个隔离实验：

> 同一页面放 6 个 `<input type="checkbox" checked>`，**只改一条声明**，逐字节比较截图。

| 变体 | `computed color` | `accent-color` | 截图字节 | 判定 |
|---|---|---|---|---|
| a 默认 | `rgb(0,0,0)` | `auto` | 373 B | 基准 |
| b `color:#274C93` | `rgb(39,76,147)` ✅ 已应用 | `auto` | **373 B（与 a 逐字节相同）** | **`color` 对原生勾无效** |
| c `accent-color:#274C93` | `rgb(0,0,0)` | `rgb(39,76,147)` | 412 B（不同） | **`accent-color` 才生效** |
| d 两者都写 | `rgb(39,76,147)` | `rgb(39,76,147)` | 412 B（= c） | 同上 |

稳定性对照：同一元素连截两次**逐字节相同** ⇒ 这个方法在本机可用。

⇒ **结论**：`text-brand-600` 写在原生 checkbox 上，**computed 里能看到颜色已应用，
但渲染出来的勾一个像素都没变**。这是「判据只读 computed style 会假绿」的又一个实例 ——
比文本那边的「空态假绿」更隐蔽，因为**值是"对"的**。

### 2.1 解码像素看真实颜色

| 变体 | 主色 | 占比 | 对白底 |
|---|---|---|---|
| a 默认勾 | `rgb(0,117,255)` | 79.9% | **4.21:1 ✓** |
| c `accent-color` 品牌 | `rgb(39,76,147)` | 80.0% | **8.26:1 ✓** |
| g 自绘（`appearance:none` + SVG 勾 + `border:#D8DEE8`） | 勾 `rgb(39,76,147)` 8.26 ✓ / **边框 `rgb(216,222,232)` 1.35 ✗** | — | 自绘时**边框**才是新坑 |

⇒ 默认勾**本来就过 3:1**（4.21），所以 ① **不是缺陷、是"代码在撒谎"**：作者以为在设品牌色，
其实什么都没设。真修它的理由是「**让代码说的话成真** + 品牌一致性」，不是「修对比度」。

## 4. 事实①：4 处 checkbox 的 class 里**只有一半生效**

`DataTable` 那 4 行写的是：

```tsx
className="h-3.5 w-3.5 rounded-[3px] border-line text-brand-600 focus:shadow-focus"
```

| class | 对原生 checkbox 是否生效 | 依据 |
|---|---|---|
| `h-3.5 w-3.5` | ✅ 生效 | 尺寸由 UA 样式表接受 |
| `focus:shadow-focus` | ✅ 生效 | `box-shadow` 不依赖 appearance |
| `text-brand-600` | ❌ **无效** | §2 的像素实验 |
| `border-line` | ❌ 无效 | `appearance:auto` 下 UA 自己画边框，不吃 `border` |
| `rounded-[3px]` | ❌ 无效 | 同上，不吃 `border-radius` |

⇒ 5 个 class 里 **3 个是装饰性的谎话**。改 `accent-brand-600` 之后：
浅色 `#274C93` 对白卡 **8.26 ✓**、深色 `#3A63B0` 对深色卡 **3.05 ✓**（与现状 4.21 相比更宽）。

### 4.1 `accent-brand-600` 在本项目**可用**（已实测，不是推断）

项目 `tailwindcss 3.4.17`，`tailwind.preset.ts` 把 `brand` 放在 `extend.colors` 下
⇒ Tailwind 的 `accentColor` 默认继承 `theme('colors')`。用最小配置跑 CLI 实测生成：

```css
.accent-brand-600 { accent-color: rgb(var(--brand-600) / 1) }
```

⚠️ **未验证**：没在真页面上跑过（隔离实验证明的是**浏览器行为**，不是本项目产物）。
落地后必须用一次渲染测量复核（见 §8）。

## 6. 选项与推荐

### ① checkbox（4 行）

- **A（推荐）**：`text-brand-600` → `accent-brand-600`。让品牌色真生效（4.21 → 8.26 / 5.85）。
- B：删掉 `text-brand-600`，保持 Chrome 默认蓝（承认"不打算用品牌色"）。
- C：自绘（`appearance:none` + SVG 勾）。⚠️ 会引入**边框**新坑（实测 `#D8DEE8` 对白底只有 **1.35**），
  要连边框一起设计 ⇒ 成本最高，**不推荐在这一轮做**。

### ② 排序箭头·激活 + ③ im 图标

- **A（推荐）**：都换 `text-link`。与上一轮文本的结论**同一条规则**，零新增令牌。
- B：新增角色令牌 `--icon-accent`（浅 = `brand-600`、深 = `brand-400`）。
  语义最准（图标 ≠ 链接），但要动 `tokens.css` + 全部判据镜像 + `design-spec.md`，
  且**多一个令牌就多一处要守**。若将来图标/链接要分家再走这条。
- C：只在深色档写 `dark:text-brand-400`。**不推荐**：两档分裂，下一个人「统一一下」就改回去。

### ③ 排序箭头·静置（**唯一需要设计判断**）

- **A（推荐）**：`ink-300` → `ink-500`（1.36 → 4.83）。理由：它是「可排序」的唯一提示，属可交互组件。
- B：不动，认定它是装饰。⚠️ 但那样就必须同时接受「浅色 1.36:1 的箭头几乎看不见」。

### ④ 通知图标 brand（3.05）

- **A（推荐）**：不动，只登记为"压线观察项"。
- B：顺手也换 `--link`（→ 7.43），与 ②③ 保持一条规则。代价：9 种类型里 1 种的颜色会变。

### ⑤ 要不要建判据（**本材料最值得单独拍的一条**）

现状：**这一类缺陷 T4 结构上看不见** —— `verify_contrast.py` 只量**文本节点**，
图标（SVG）、边框、原生控件填充全部在它的盲区外。三个方向：

| 方向 | 能抓到什么 | 成本 |
|---|---|---|
| **源码层**：`<input type="checkbox">` 上禁止出现 `text-*` | ①（死类） | 低。但要按**形状**扫（元素 + 属性），不能只认字面量 |
| 渲染层：量 `accent-color` / SVG `fill` / 边框色 | ②③④ + ① | 中高。要新增一个「非文本」测量通道，且**必须读像素或读 used value**（computed `color` 会假绿，§2） |
| 不建 | — | 0，但这类问题只能靠人眼 |

⚠️ **别急着建只认字面量的判据**（`text-brand-*`）—— 上一轮就是这么漏掉
`CitationPanel` / `KpiCard` / `ProvenanceBadge` 的（`ruling-token-tier-2026-10-29.md` §10.2）。
