## 01 设计定位与原则

关键词：**可信、克制、密实、可追溯**。

1. **信任优先于惊艳** — 不用大面积渐变、发光阴影、卡通插画；用留白、对齐、克制色彩建立信任。
2. **边界必须可见** — AI 生成 / 律师确认 / 待复核 必须是一等视觉语言，任何法律内容都携带可识别状态。
3. **信息密度是美德** — 放弃大卡片门户，改用侧栏 + 密集列表 + 表格。
4. **数字与案号必须对齐** — 金额、案号、日期、条款号全部等宽 + `tabular-nums`。
5. **移动端不是缩小版** — 高频、碎片、移动场景明确的动作必须原生适配（详见第 08 节）。

### 与现有品牌的关系

保留靛蓝色相作为识别锚点，但下沉到墨蓝区间：`#4F46E5 → #274C93`（同色相，明度降 34%、饱和度降 21%）。
点缀色由亮金 `#F5B942` 改为香槟金 `#B08A4F`。

## 03 字体排印

### 3.1 三套字体栈

| 用途 | 字体栈 |
|---|---|
| UI 无衬线 | `Inter, "PingFang SC", "Microsoft YaHei", system-ui` |
| 衬线 · 法条与文书 | `"Noto Serif SC", "Source Han Serif SC", "Songti SC", Georgia, serif` |
| 等宽 · 数字与编号 | `ui-monospace, SFMono-Regular, Menlo, Consolas` |

Inter 负责西文与数字，中文回退系统字（避免加载 3–8 MB 中文字体包）。
衬线体仅用于法条原文、引用摘录、文书正文——这是最重要的差异化手段。

### 3.2 字号阶梯

| Token | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| caption | 11px / 1.5 | 500 | 免责声明、图表轴标签、时间戳 |
| label | 12px / 1.5 | 500 | 表单标签、表头、徽章、元信息 |
| body-sm | 13px / 1.65 | 400 | 表格单元格、列表次要行 |
| **body** | **14px / 1.7** | 400 | **基准**：正文、对话气泡、描述 |
| body-lg | 15px / 1.85 | 400 | 法条原文、长文阅读（配衬线） |
| h4 | 16px / 1.5 | 600 | 卡片标题、面板标题 |
| h3 | 18px / 1.45 | 600 | 区块标题 |
| h2 | 22px / 1.4 | 600 | 页面标题（字距 -0.01em） |
| h1 | 30px / 1.3 | 600 | 登录页、仪表盘主标题 |
| display | 38px / 1.25 | 600 | 仅品牌区 |

> ⚠️ **`caption` 的多行形态（2026-09-24 补）**：上表 `caption` 的 **1.5 是单行形态**
> （图表轴标签、时间戳）。当 `caption` 承载**多行文本**时（免责声明全文、数据驱动的说明段落，
> 例如 API 返回的 `disclaimer` / `note` / `description`），可用 **`leading-relaxed`（1.625）**
> 提升可读性。
> **依据**：§3.3 规则 2 的 **1.65 地板只约束「正文」**，`caption` 不属正文 ⇒ **不受该地板约束**；
> 但 11px 中文在 1.5 行高下**多行偏紧**，故允许提升到 1.625。
> ⚠️ **1.625 是 Tailwind 默认主题的值，本项目 preset 未覆写 `lineHeight`** ⇒ 它属**上游默认值**、
> 未被项目固化；若要彻底固化，应新增语义档（本轮**未采纳**）。
> 落地现状：四端共 **15 处**（存证 `evidence/caption_lineheight_spec_gap_2026-09-24.txt`）。

### 3.3 中文排印三条硬规则

1. **字重只用 400 / 500 / 600** —— 中文 700 在 Windows 上渲染为合成粗体，边缘发糊。
2. **正文行高 ≥ 1.65** —— 中文方块字密度高；法条原文用 1.85–2.0。
3. **中英混排加 0.25em 间隙** —— 避免「3件」这类粘连。

## 04 布局 · 间距 · 圆角 · 阴影

### 4.1 AppShell（桌面形态）

- 左侧 **240px** 墨色导航（< 1024px 收起为抽屉，**不做 64px 图标条**）
- 顶部 **56px** 栏：面包屑 + 全局搜索（⌘K）+ 通知 + 用户菜单
- 内容区最大宽 **1280**（工作台）/ **1600**（驾驶舱）/ **720**（阅读型页面）
- 侧栏顶部含**应用切换器**，打通 web / lawyer / admin 三端

### 4.2 间距（4pt 网格）

刻度：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80

- 桌面页面内边距 24px；**移动端 16px**
- 卡片内边距：16px（紧凑）/ 20px（常规）/ 24px（宽松）
- 卡片之间 16px；同一面板内元素 12px；区块之间 32–40px；表单字段之间 16px
- 图标与文本间距 6–8px
- 禁止出现 5px / 13px / 18px 等游离值

> ⚠️ **范围界定（2026-09-26 补 · §9 第 24 项裁定 ②）**：本条的**游离值指「间距」** ——
> `padding` / `margin` / `gap` / `space` 这类**间距语义**属性上的手写魔数。
> **装饰性定位偏移不在此列**：例如 `aria-hidden` 的连接线用 `top-[5px]` / `left-[7px]`
> 把线与兄弟节点的圆点对齐，偏移量由**兄弟节点尺寸推导**，不是随手挑的数值。
> 若按字面推广，会**拿规范的字面否定规范自己** —— 本节上文又明文允许 **6px** 半档，
> 而 6 并不是 4 的倍数。
> ⇒ **门禁口径**：**S1 / S2 只判「间距属性」**；**定位属性上的游离值只报不判**
> （`evidence/verify_spacing_scale.py` 的 S3）。
> ⇒ 另：**Tailwind 默认间距刻度是 2pt**（`0.5`=2 / `1.5`=6 / `2.5`=10 / `3.5`=14 / `7`=28 …），
> 命名档里的半档**都来自它**（全仓 260+ 处）—— 这是**规范与 Tailwind 的 tension**，
> 不是缺陷，同样**只报不判**（S4）。

栅格：12 列，gutter 24px，断点 640 / 1024 / 1280 / 1600。

### 4.3 圆角 / 阴影 / 边框

| Token | 值 | 用途 |
|---|---|---|
| `--r1` | 4px | 徽章、标签、小按钮 |
| `--r2` | 6px | 按钮、输入框、列表项 |
| `--r3` | 8px | 卡片、面板、表格容器 |
| `--r4` | 12px | 模态、抽屉、输入区大框 |

废弃 16px 及以上圆角。

| Token | 值 | 用途 |
|---|---|---|
| `--s1` | `0 1px 2px rgba(16,24,40,.06)` | 卡片静置 |
| `--s2` | `0 4px 12px -2px rgba(16,24,40,.10)` | hover、下拉 |
| `--s3` | `0 16px 40px -8px rgba(16,24,40,.18)` | 模态、抽屉 |

> 法律产品**优先用 1px 边框而非阴影**划分区域——阴影轻飘，边框稳定。

焦点环统一：`0 0 0 3px rgba(54,96,176,.22)`。

### 4.4 动效

| 场景 | 时长 | 缓动 |
|---|---|---|
| hover / 颜色变化 | 120ms | ease-out |
| 展开 / 折叠 | 180ms | `cubic-bezier(.2,.8,.2,1)` |
| 抽屉 / 模态 / 底部 Sheet | 240ms | `cubic-bezier(.2,.8,.2,1)` |
| 流式打字光标 | 1.2s 循环 | ease-in-out |
| 加载指示（旋转） | 1s 循环 | ease-linear |

必须响应 `prefers-reduced-motion: reduce`。

> **补充（2026-09-25 · #75）· 加载指示的动效**
>
> 「加载指示（旋转）」对应令牌 `--dur-spin: 1s` / `--spin-iter: infinite`，
> 经 `tailwind.preset.ts` 的 **`animate-spin-soft`** 工具类消费；唯一消费者是共享原语
> **`<Spinner>`**（`packages/ui`）。
>
> 🚨 **不许用 Tailwind 内置的旋转类**（写作 `animate-` + `spin`）：它把时长写死成
> `1s linear infinite`、**不读 `--dur-*`** ⇒ reduce 下照转不停。该内置类已被门禁
> `verify_motion_tokens.py` 的 **A4** 禁止（全仓 **0 处**）。
>
> **reduce 下的形态：停成静止的弧**（不是继续转，也不是消失）。
> 理由：停掉**指示器**会让用户以为界面卡死 ⇒ 指示器必须保留；
> 而「**旋转**」才是前庭反应的触发形态 ⇒ 归零的是旋转。
> 与骨架屏同一口径（`--dur-pulse: 0ms`）—— **要么都归零、要么都不归零**。
> 收敛与裁定过程：`design-spec-addendum`… 见 `motion-spin-audit.md`。

## 05 责任边界三态系统

| 状态 | 视觉 | 徽章 |
|---|---|---|
| **AI 生成** | 紫色虚线上边框 + 浅紫底 | `✦ AI 生成` |
| **律师已确认** | 绿色实线左边条 3px + 浅绿底 | `✓ 律师已确认` + 确认人与时间 |
| **待复核 / 风险** | 琥珀左边条 + 浅琥珀底 | `⏱ 待复核` |

### 使用规则

1. **穷尽性** —— 任何法律内容必须且只能属于三态之一，不允许「无状态」内容。
2. **全局图例** —— 问答页、文书页、案件详情页顶栏常驻三态图例（移动端置于问题标题下方）。
3. **状态可迁移** —— AI 生成 → 律师确认 单向、留痕；徽章可点击查看流转记录。
4. **导出保留** —— 导出 PDF / Word 时三态标记必须保留（合规要求）。
5. **颜色不可独立承载语义** —— 必须「颜色 + 文字 + 图标」三重编码。

> **决策 08 已确认**：三态需要后端落库。需新增 provenance 数据模型（内容段级的状态、确认人、时间、流转记录）。

## 08 移动端设计规范

法律服务的真实使用场景大量发生在手机上：客户半夜遇到纠纷先掏手机问一句、律师在法院走廊等开庭时翻案卷、
企业法务在会议室里核对条款、HR 在招聘现场拍一份劳动合同回来扫描。
**移动端不是「桌面端的缩小版」，而是需要独立设计的第二主场。**

> **立场**：移动端优先（Mobile First），但**不是所有页面都要移动化**。
> 运营驾驶舱的复杂图表、文书编辑器的长文排版仍以桌面为主。

### 8.1 各端移动端优先度

| 端 | 移动端定位 | 必须移动适配的功能 |
|---|---|---|
| **im（客户端）** | 移动优先 | 全部。C 端客户几乎只用手机，**设计基准直接按 375px 起草**，桌面视为放大适配 |
| **web（企业法务）** | 移动优先 | 登录、工作台、问答、合规扫描（拍照即扫）、案件进度、通知、我的。文书编辑器仅支持移动端预览与批注 |
| **lawyer（律师端）** | 移动强需求 | 派单池（抢单）、案件阅读、证据拍照上传、复核审批、沟通记录、工时填报。卷宗整理以桌面为主 |
| **admin（运营后台）** | 桌面为主 | 仅支持**只读查看**：驾驶舱核心指标、告警、案件查询。批量操作、规则配置不移动化 |

### 8.2 断点与布局切换

| 断点 | 宽度 | 导航形态 | 内容区 |
|---|---|---|---|
| `compact` | < 640px | 底部 Tab Bar + 顶部 AppBar | 单列，页边距 16px；表格转卡片 |
| `medium` | 640 – 1023px | 底部 Tab Bar（平板可改侧栏图标态） | 单列为主，允许两列卡片；页边距 24px |
| `expanded` | 1024 – 1599px | 侧栏 240px 常驻 | 12 栅格，页边距 24px，内容最大宽 1280 |
| `wide` | ≥ 1600px | 侧栏 240px 常驻 | 驾驶舱全宽（1600），其余保持 1280 |

> ⚠️ **修订（2026-09-23）**：`wide` 原写 `≥ 1440px`、`expanded` 原写 `1024 – 1439px`，
> 与 §4.2「断点 640 / 1024 / 1280 / **1600**」及 `tailwind.preset.ts` 的 `screens.wide = 1600px`
> **自相矛盾**（**1440 在实现里根本不存在** —— 全仓 `wide:` 工具类 **0 处**）。
> 现按 **1600** 对齐（1600 有三处实现支撑：`screens.wide` / `maxWidth.wide` / `--content-wide`），
> 并把 `expanded` 上界一并改为 **1599**，**以消除 1440–1599 的空档**（只改 `wide` 会留空档）。

> ⚠️ **脚注（2026-09-26 补 · §9 第 11 项裁定 ②）：本表对 `im`（客户端）不适用。**
> 依据 §8.1「桌面视为放大适配」+ 决策 12「IM 端形态 ✓ 桌面三栏」+ 概念图 `288px 1fr 320px`
> ⇒ im 桌面**满屏三栏、无导航侧栏**。理由：桌面 1280px 下再叠 240px 导航，**正文只剩 432px**，
> 连一段法条都放不下（`apps/im/app/(app)/layout.tsx` 已写明）。
> ⇒ **`im` 的断点只切「三栏 ↔ 单栏」，不出现侧栏形态。**
> ⚠️ **§4.1 的 240px 不改** —— 那是 web / lawyer / admin 三端的正确值。

**关键规则**：侧栏在 < 1024px 时**不折叠成 64px 图标条，而是完全收起为抽屉**——
64px 图标条在手机上仍占用宝贵宽度，且图标无语义提示时难以辨认。

### 8.3 触控目标与拇指热区

**触控目标**
- 最小 **44 × 44px**（Apple HIG / WCAG 2.5.5）
- 本项目标准 **48 × 48px** —— 法律产品用户年龄跨度大，含 45+ 律师与客户
- 列表行高 ≥ 48px；主按钮高度 48px
- 相邻可点元素间距 ≥ 8px，避免误触
- 图标按钮必须有 48px 的**不可见热区**，即使图标只有 20px

> **脚注（2026-09-25 定稿）· 并排小目标的相容阈值 `W ≥ 40px`**
>
> 上面「相邻可点元素间距 ≥ 8px」与「48px 不可见热区」两条，对**可视盒 < 40px 的并排目标**
> **在数学上不相容**。设盒宽 `W`、间距 `g`、热区 `H = 48`，热区**每侧**外扩 `(H − W) / 2`，
> 两热区不重叠 ⇔ **`g ≥ H − W`**。代入 `g ≥ 8` ⇒ **`W ≥ 40px`**。
>
> | 盒宽 `W` | 热区每侧外扩 | 不重叠所需最小间距 | 与 `g ≥ 8px` 相容？ |
> |---|---|---|---|
> | 32px | 8px | 16px | ❌ 差 12px |
> | **40px** | **4px** | **8px** | ✅ **相容阈值** |
> | 44px | 2px | 4px | ✅ |
> | 48px | 0 | 0 | ✅（热区 = 盒） |
>
> **实现约定**：并排的小目标盒宽取 **≥ 40px**（`min-w-10`），间距取 **8px**（`gap-2`）。
> ⚠️ **宽度侧必须无条件生效**（不能只在移动端放大）—— 判据量的是**水平相邻**，桌面档同样在扫；
> `min-h-tap` 只解决**高度**，不能替代宽度达标。
> 定稿记录（含完整算术与实测）：`design-spec-addendum-8.3-tap-targets.md`；
> 判据：`evidence/verify_adjacent_targets.py`。首轮实测全仓唯一命中处 `Pagination` 已按此修
> （`h-10 min-w-10` + `gap-2`）⇒ `[A1]` **4 对 → 0 对**。

**拇指热区**
- 底部 1/3：主操作、Tab Bar、输入框
- 中部：内容阅读区
- 顶部：仅放标题、返回、低频操作
- 「AI 提问」入口放在首页**首屏中下部**，不放顶部
- 破坏性操作（删除、退回）不放右手拇指自然落点

**安全区与手势**
- 所有固定底部元素加 `env(safe-area-inset-bottom)`
- 顶部状态栏区域留 44px（刘海屏 / 灵动岛）
- 底部 Home Indicator 区高 34px，不放可点元素
- 支持左滑返回；右滑不绑定操作

### 8.4 导航模式

- **客户端 4 项 Tab**：工作台 / 咨询 / 我的案件 / 我的
- **律师端 5 项 Tab**：工作台 / 派单池 / 案件 / 复核 / 我的（派单池红色待办角标、待同步琥珀角标）
- **律师端额外有常驻底部操作条** —— 办案中「确认本段」「提交复核」需随时可点，不藏菜单里
- **运营后台**：AppBar + 只读标识，无 Tab Bar
- Tab Bar 不超过 5 项；次级功能（归档 / 工时 / 模板库）收进「我的」或工作台快捷入口

### 8.5 表格转卡片规则

| 桌面表格特征 | 移动端形态 | 转换规则 |
|---|---|---|
| 列数 ≤ 3，行数 ≤ 8 | 保留表格 | 隐藏表头，首列 + 右侧值形式展示 |
| 列数 4 – 6 | **卡片列表**（首选） | 主标识 + 状态徽章置顶；其余字段两列网格；操作按钮置于卡片底部 |
| 列数 > 6 | 卡片列表 + 详情页 | 卡片只保留 3 个关键字段，其余进详情页 |
| 需横向对比数值 | 横向滚动 + 首列冻结 | 仅驾驶舱等强对比场景，必须显示滚动提示 |

案号、金额、日期在移动端**仍保持等宽字体**，字号可降至 11–12px 以节省宽度。

### 8.6 弱网与离线

律师在法院、看守所、地下停车场经常没有信号。这是法律行业特有、必须在设计阶段解决的场景。

**离线可读**
- 打开案件时**预缓存**六段式分析、证据索引、文书正文（单案上限 20 MB）
- 缓存状态在证据列表用 ✓ 明示
- 离线模式下顶部显示琥珀色状态条，并提供「重试」入口

**待同步队列**
- 离线期间的拍照、批注、状态变更全部进队列，不报错、不丢失
- 队列项显示进度与状态（上传中 / 等待）
- 恢复网络后**自动补传**，Tab 角标用**琥珀色**区分「待同步」与「待办」（红色）
- 冲突处理：以服务端为准，本地变更保留为批注草稿
