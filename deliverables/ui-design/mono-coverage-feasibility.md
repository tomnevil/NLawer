# §1 原则 4「全站等宽」可静态判性 —— 小样本实测

> 2026-09-25 · 对应待办 **#58**（`design-audit.md` §14.4 候选 ②）
> **任务要求**：先实测，**先别写门禁**，据此下「可静态判 / 需渲染 / 不成立」三选一。

## 结论（先说）

**「全站」这一形态 —— 不成立。** 纯静态判会在**残余集**上产出 **68% 假红/误判**。

但「不成立」只否定**一种形态**，不否定这件事本身。真能判的有两条路，见 §5。
**推荐替代 1（逐组件契约）**：立即可做、零假红、成本线性 —— 先例就是现有的 `judge_j7`（KpiCard）。

---

## 1. 要求与出处

`deliverables/ui-design/§1「4. 数字与案号必须对齐 — 金额、案号、日期」`（§1 原则 4）：

> **数字与案号必须对齐** — 金额、案号、日期、条款号全部**等宽 + `tabular-nums`**。

配套：`:146` 等宽字体栈 = `ui-monospace, SFMono-Regular, Menlo, Consolas`；`:478` 移动端仍保持等宽（字号可降 11–12px）。

## 2. 现状：载体存在、且被广泛使用（这一半是好的）

`frontend/packages/ui/src/styles.css:53`：

```css
/* 金额、案号、日期、条款号：等宽 + 表格数字对齐 */
html .num {
  font-family: var(--font-mono);
  font-variant-numeric: tabular-nums;
  font-feature-settings: "tnum" 1;
}
```

| 载体 | 用量（apps + packages，排除 `.next`） |
|---|---|
| `className="num…"` | **141** 处 |
| 裸 `tabular-nums` | **4** 处（`im/page.tsx:177`、`im/page.tsx:187`、`CountBadge.tsx:50`、`StageProgress.tsx:100`） |
| `font-mono` | 0 处 |

⚠️ **裸 `tabular-nums` 的 4 处不是缺陷**：它们渲染的是**计数/百分比**（`{pendingTotal} 项` / `{pct}%`），
**不在 §1 原则 4 列举的四类里**（金额/案号/日期/条款号）⇒ 判据若把「所有数字」纳入范围就会**第一天假红**。

⇒ **可判的是「反向」**：*哪个该用 `num` 却没用*。而那正是需要**语义**的部分。

## 3. 实测方法（可复现）

- 范围：`frontend/apps` + `frontend/packages` 下 **89 个 `.tsx`**，跳过 `node_modules` / `.next` / `dist` 等。
- 抓 JSX 插值 `{expr}`（单层括号，≤120 字符），先按**字段名词表**判类别：
  金额（`amount|price|fee|balance|cost|revenue|expense|money|budget|金额|费用|标的额|yuan(`）·
  案号（`case_no|caseNo|caseNumber|docket|案号`）· 日期（`createdAt|updatedAt|dueAt|deadline|…`）·
  条款号（`clause|article_no|article|条款`）。
- 再剔**结构性噪声**（JSX 注释 / 对象字面量 / 类型注解 / 展开运算符 / 语句解构）。
- 对残余逐处看**本行 + 前 3 行**有没有等宽类，标「疑似已带 / 疑似未带」。
- ⚠️ 摸底脚本**刻意不落 `evidence/`**（判据 0b 要求那里每个 `.py` 都表态），用完即删。
  ⚠️ **实测踩到自己一次**：第一版把「与金额无关的对象字面量」也计进噪声桶 ⇒ 噪声率虚高成 **94.7%**。
  修正后真实数字见下（**先按类别命中、再分噪声**，顺序不能反）。

## 4. 结果

```
扫描 89 个 .tsx · JSX 插值 3627 处 · 类别命中 52 处
其中结构性噪声 13 处（25.0%）：对象字面量 11 · 类型注解 2
→ 疑似真渲染 39 处（未带等宽 19）

  条款号  真渲染 12 · 未带等宽 10
  案号    真渲染 12 · 未带等宽  3
  金额    真渲染 14 · 未带等宽  6
  日期    真渲染  1 · 未带等宽  0
```

**关键不在 25% 的原始噪声，而在「剔完噪声之后」。**
对 19 处「未带」**逐条人工核**，结果是：

| 类别 | 条数 | 判定 | 例子 |
|---|---|---|---|
| **A. 等宽在组件内部**（`value=` prop） | **4** | ❌ 假红 | `admin/page.tsx:385` `value={Math.round(…amount_cents…/100)} unit="元"` ⇒ `num` 在 **KpiCard 内部**（`judge_j7` 判的就是它） |
| **B. 不是渲染文本**（属性 / 模板串 / 解构） | **5** | ❌ 假红 | `admin/cases/page.tsx:565` 模板串喂 `title=`；`lawyer/cases/[id]:1634` `findIndex` 里的模板串（**纯逻辑**）；`qa/page.tsx:105` `const { name, article } = …` **解构赋值** |
| **C. 显式 `mono` prop** | **2** | ❌ 假红 | `im/cases/[id]:146` `<Row … mono />`、`lawyer/cases/[id]:1170` `<KV … mono />` —— **作者显式开了等宽**，静态规则看不见 prop |
| **D. 语义误判** | **2** | ❌ 误判 | `web/documents/page.tsx:457/458` `…{f.clause}…` 是 `font-serif` 的**摘录正文**（`clause?: string` 存原文片段），**不是条款号** |
| **E. 真·疑似违规** | **6** | ✅ 真 | `admin/cases/page.tsx:318` `{row.case_no}` · `admin/reviews/page.tsx:713` `《{law_name}》{article_no}` · `reviews/page.tsx:732` · `im/chat/page.tsx:970` · `lawyer/cases/[id]:1523` · `CitationPanel.tsx:101` |

⇒ **19 处里 13 处（68.4%）是假红/误判，只有 6 处（31.6%）是真违规。**

## 5. 为什么「全站」不成立（三条根因，各对应上表一类）

1. **等宽可能不在调用点，而在组件内部**（A 类 4 处）。静态文本看不见「这个 prop 最终会不会被渲染成等宽」——
   要判就得**逐组件知道契约**（KpiCard / `Row` / `KV` 各自怎么处理 `mono`）。
   ⇒ 「全站」规则**必然**把 A 类全判成假红。
2. **表达式 ≠ 渲染文本**（B 类 5 处）。属性值、模板串、解构、`findIndex` 比较……都在 `{}` 里，但都不渲染。
   ⇒ 需要**真 JSX AST**，而不是「行内正则」。（本项目现有探针的 `className` 块扫描器**已有**括号配对能力，所以这一类**可以**被消掉 —— 但消掉之后还剩 A/C/D 三类。）
3. **字段名 ≠ 语义**（D 类 2 处 + 裸 `tabular-nums` 4 处）。`total` 既可能是**分页计数**也可能是**金额**；
   `clause` 既可能是**条款号**也可能是**摘录正文**；`article` 在 `CitationPanel` 是条款号、在 `qa/page.tsx` 是解析出的对象字段。
   ⇒ 「哪些字符串算金额/案号/日期/条款号」是**语义分类**问题，**静态判不了**。

⚠️ 这不是「判据写得太粗」，而是**判据的表达能力**不够：
**「该处是否属于那四类」这个前提，在源码文本里根本没有可靠信号。**

## 6. 可行的三条替代

| | 做法 | 成本 | 假红 | 覆盖 |
|---|---|---|---|---|
| **① 逐组件契约**（**推荐**） | 把原则 4 拆成「**每个渲染金额/案号/日期/条款号的组件**，其内部必须带 `num`」。已可复用：`judge_j7`（KpiCard 数值）· `Row`/`KV` 的 `mono` prop · `DataTable` 的列 `align`/`render` | 每组件一条判据 | **0**（「该组件负责渲染什么」是**已知**的，不是猜的） | 逐组件，非「全站」 |
| **② 标注 + 双向判据**（要产品配合） | 给这些节点加 `data-num`。判据：**静态**「凡 `data-num` 必须带 `num`」+ **渲染**「凡 `data-num`，computed style 必须 `tabular-nums` 且 `font-family == var(--font-mono)`」 | 产品加属性 + 两条判据 | **0** | **真「全站」**，且**标注覆盖率本身成为可判信号**（今天 141 处 `num`，没人知道该有多少） |
| **③ 纯渲染级** | 浏览器里断言「含金额的节点」的 computed style | 高 | **仍然要语义** ⇒ 判不了「哪个节点算金额」 | 与静态同困 |

**⇒ 推荐 ①**（立即可做、零假红、成本线性）；若要「全站」级别，须走 **②**（**需拍板**：它是产品改动 + 新判据形态）。

## 7. 顺带：6 处真违规（可独立修，不依赖判据）

上表 E 组 6 处 —— **修法不是「加个类」那么简单**：条款号/案号常与其它文字**拼在同一个字符串表达式里**
（`《{law_name}》{article_no}`、`` `${case_no}　${title}` ``）⇒ 直接给容器加 `num` 会把**法律名/标题也变成等宽**。
正确修法是**拆 `<span className="num">` 只包住编号那一段**（`admin/cases/page.tsx:318` 与
`CitationPanel.tsx:101` 两处可直接加类，其余 4 处需拆结构）。

⚠️ 这与「加个类就完事」的直觉相反 —— 也是为什么**判据不能替人做这个判断**。

## 8. 未做 / 边界

- **未写任何门禁**（任务明确要求先别写）。
- 未测**渲染**（没有起服务、没有真浏览器）⇒ 表里「疑似已带」是**源码文本**判定，不代表 computed style 真的生效
  （`num` 类是否被 Tailwind 产物收录、是否被后置类覆盖，属 `verify_typography.py` 的 T2 家族问题）。
- 词表是**小样本**（89 个 `.tsx`、52 处命中）⇒ 结论对**词表敏感**；换一份词表数字会变，但**三类根因不变**。
- 摸底脚本为一次性工具，**未入库**（用完即删）；复刻要点见 §3。
